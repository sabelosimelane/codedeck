## [2026-11-27] - Resume workflow work safely after the iteration limit

### Executive Summary
* Continuing a workflow after it reaches its iteration limit now resumes the outstanding work instead of accepting the capped step as complete. The owner can run one bounded extra round (or one pass for an until-complete step), or stop with work remaining. The original limit remains visible, each extension belongs to one specific pause, and repeated or stale clicks cannot start extra work. Workflow completion now requires fresh closing Test evidence, including a fully completed configured plan and a successful final-suite result for every changed repository. Historical runs that accepted an iteration limit are shown as “Ended at limit” rather than successful completions.
* Recovery continues through the configured Develop → Review → Test sequence. The latest Test findings are routed to the repair work, and passing checks can be carried forward only when their relevant source, inputs and environment still match. This avoids unnecessary repeat checks while retaining review and focused retesting. The incident evidence did not establish a parallel scheduling speedup, so this change does not alter role order or introduce parallel execution.
