When implementing functionality, decompose by **vertical feature slices** — each slice is a single capability built end-to-end (backend + frontend). Within each slice, work layer by layer in this order:

1. **Data layer** — SQLite schema changes if needed (new tables, columns)
2. **Service layer** — business logic functions (pure, no req/res coupling)
3. **API layer** — Express route handlers (validate, call service, return response)
4. **Unit tests** — test service functions in isolation
5. **Frontend components** — React UI that calls the API
6. **Integration tests** — test the full round-trip (API call → DB → response)

Each slice closes completely before moving on. Front-load the riskiest, most rule-heavy slices first.

## Error Handling Contract

Every vertical slice must include error handling end-to-end:

**Backend:**
- Route handler validates input → returns 400 with `{ error: "..." }` on failure
- Service function returns error objects (not throws) for expected failures
- Unexpected errors caught and returned as 500 with `{ error: "..." }`

**Frontend:**
- Every `fetch()` call checks `res.ok` and handles non-2xx responses
- Network failures (fetch throws) show "server unreachable" feedback
- Success shows a brief toast confirmation
- Failure shows an actionable error toast

A feature is not complete until both the happy path and the error path work.

## Service Layer Pattern

Service functions should be pure and testable:

```javascript
// services/projectService.js
export function addProject(name, projectPath, existingProjects) {
  if (existingProjects.find(p => p.path === projectPath)) {
    return { error: 'project already exists', status: 409 };
  }
  const project = { name, path: projectPath };
  return { data: project };
}
```

The route handler orchestrates: reads from DB, calls the service, writes to DB, returns the response. The service function itself has no side effects.
