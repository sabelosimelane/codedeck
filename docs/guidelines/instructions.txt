Follow the Well-Architected Framework for all implementation decisions.

## Architecture at a Glance
```
API Layer (Express route handlers — validate input, return responses)
    ↓ calls
Service Layer (business logic — pure functions, no req/res)
    ↓ calls
Data Layer (SQLite via better-sqlite3 — schema, queries)

Frontend (React)
    ↕ REST + WebSocket → Backend
    → All state mutations go through the backend
    → Every API call has error handling and user feedback
```

## Anti-Patterns (Forbidden)

❌ Silent error swallowing (`catch(() => {})` or `.catch(() => {})`)
❌ Frontend holding authoritative state (localStorage as source of truth)
❌ API calls without error handling or user feedback
❌ Business logic in route handlers (extract to service modules)
❌ Business logic in React components (data flows from backend)
❌ Raw SQL scattered across route handlers (use db helper functions)
❌ Unsanitized user input in shell commands
❌ Optimistic UI updates without backend confirmation and rollback

✅ Backend is the single source of truth for all state
✅ Every user action that modifies state round-trips through the backend
✅ Success and failure both produce user-visible feedback (toasts)
✅ Validate at every backend route handler (required fields, types, path existence)
✅ Structured error responses: `{ error: string, detail?: string }`
✅ WebSocket disconnect/reconnect is handled and visible to the user
✅ Service functions are testable without Express (no req/res coupling)
✅ File paths validated before passing to any system command

## Pre-Commit Checklist

- [ ] No silent error swallowing anywhere in changed files
- [ ] Every new/modified API call in the frontend handles errors and shows feedback
- [ ] State mutations go through the backend, not just local React state
- [ ] New route handlers validate input before processing
- [ ] File/directory paths are validated before use
- [ ] WebSocket handlers handle disconnect gracefully
- [ ] Backend returns structured error responses with appropriate HTTP status codes

## Frontend Pre-Commit Checklist

- [ ] No hardcoded error messages — read from API response `error` field
- [ ] Generic fallback for unexpected errors ("Something went wrong. Please try again.")
- [ ] Toast notifications for success and failure on all mutating actions
- [ ] Loading states shown for operations that may take time
- [ ] Connection-lost state is visible when backend is unreachable
